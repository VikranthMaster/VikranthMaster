# Setup

## 0. Create the repo
The repo name has to be **exactly your GitHub username** for a README here to
show on your profile page.

```bash
gh repo create VikranthMaster --public --clone
cd VikranthMaster
# copy everything from this folder in, then:
git add -A && git commit -m "init" && git push
```

If your GitHub username isn't `VikranthMaster`, update it in two places:
- `GH_LOGIN` default in `scripts/generate_stats.py` (or just rely on
  `.github/workflows/stats.yml`, which already uses
  `${{ github.repository_owner }}` automatically — no edit needed there)
- links in `README.md`

## 1. Turn on the stats workflow
Nothing to configure — `.github/workflows/stats.yml` uses the repo's built-in
`GITHUB_TOKEN`, no personal access token needed. Either wait for the nightly
cron (`17 5 * * *` UTC) or trigger it once by hand:

```bash
gh workflow run "refresh stats"
```

That fills in real numbers for `stats.svg`, `streak.svg`, `langs.svg`, and
`year.svg`. The five heading images (`hd-*.svg`) are already generated and
committed — you don't need the workflow for those, they don't depend on API
data.

## 2. Add your portrait (local machine, not this environment)
This step needs a real photo and ~200MB of ML dependencies, so run it on your
own machine:

```bash
pip install pillow numpy opencv-python-headless rembg onnxruntime
python3 scripts/make_portrait.py your-photo.jpg --crop LEFT,TOP,RIGHT,BOTTOM
python3 scripts/embed_portrait_font.py
```

Photo checklist (this is what actually determines quality — no parameter
fixes a bad input):
- side light, ~45°, one side of the face in shadow
- crop tight: chin to just above the hair
- at least 1200px on the long edge before cropping
- plain background

Commit the resulting `ascii.svg` — it's a one-off, not regenerated by the
workflow.

## 3. Edit the text
`README.md` has placeholder links (LinkedIn, email) — swap those in. The
project blurbs already reflect what's in your repos; edit as they change.

## Gotchas
- A full-page headless-Chrome screenshot restarts the SMIL animation — use a
  tall viewport instead if you're checking it locally.
- A newly created profile README is sometimes cached — edit it once through
  the GitHub web UI to force a refresh if it doesn't show up.
- Test any markdown changes against `POST /markdown` (GitHub's rendering API)
  before assuming a tag will survive — GitHub strips `<style>`, `style=`,
  inline `<svg>`, `<font>`, `<small>`, `<big>`.
